# 0011. JFLAP `.jff` import and export

Status: accepted

## Context

Fasilkom UI students and lecturers make their machines in JFLAP, so files must move between JFLAP and WebTomata. A `.jff` file is XML from outside the app, so it is untrusted input. JFLAP has no alphabet of symbols: it reads a transition label as a string of characters, and a label of several characters is read one character after the other (confirmed by a student who used JFLAP in the course). Our engine reads symbols, and a symbol such as `num` is one unit.

## Decision

- Dependency: `roxmltree` 0.21.1 (MIT or Apache-2.0, no dependencies, `forbid(unsafe_code)`), used with DTDs refused and a node limit. Writing XML needs no library.
- `parse_jff(xml) -> Result<Jff, Message>` where `Jff` holds the `fsm`, the `states` (id, name, x, y; the engine keeps names and positions out of the machine) and `notes`. `to_jff(&Fsm, layout) -> Result<String, Message>` writes plain XML, in a fixed order, with `q<id>` names and grid positions for states that have no layout.
- Only `<type>fa</type>` is read; other types give `jff.unsupported_type { type }`. At most 1 MiB. The machine limits of E1 apply. XML errors give `jff.xml_invalid { line, column }`, wrong shapes give `jff.invalid_structure { element, line }`, more than one initial state gives `jff.multiple_initial_states`, problems in the machine reuse `machine.*` messages.
- The alphabet is the sorted set of characters that are read. The kind is `dfsm` if there is no ε-transition and no state has two transitions on one symbol, otherwise `ndfsm`. An empty `<read/>` is ε. A missing initial state is allowed (validation warns about it).
- A label of several characters becomes a chain of transitions through new states with ids after the highest state (`m<id>` names, positions between the two ends), and a note `jff.label_expanded { label, from, to }` tells the UI. This keeps the meaning that JFLAP gives the file and leaves the engine unchanged. A symbol with several characters cannot be exported (`jff.symbol_not_single_character { symbol }`). Symbols that no transition reads are not written.
- Export escapes `& < > " '`, replaces characters that XML 1.0 cannot hold with `?`, and turns tabs and line breaks in names into spaces.
- Fuzzing: a `fuzz/` crate (its own workspace, nightly only) with two `cargo-fuzz` targets, `parse_jff` and `parse_json`, which also check that what is read survives a write and a read. The workflow `fuzz.yml` runs each target for 60 seconds on pull requests that touch the engine, and weekly. It is not a required check. The normal tests also run random and damaged input through the parsers.

## Consequences

- The JFLAP reader is the only code that reads untrusted XML; it can be checked in one place.
- `libfuzzer-sys` (MIT or Apache-2.0, with an NCSA part from LLVM) is used only in the fuzz crate and never ships.
- Layout algorithms (S9) can replace the grid positions of exported files.
