## 9. Deepening pass

- **New exports / public members:** `visibleEntries` (`library.ts`) and `Entry.empty`. `visibleEntries`
  cannot be private: `vitest.config.ts` runs plain TypeScript with no Svelte plugin, so the filter rule
  cannot be tested through `Library.refresh()`; `library.ts` is already the module of rules without a
  framework (its header says so), and `refresh()` is the shell that applies the rule. `Entry.empty` is
  the one new member, needed by both the filter and the tests. No other export was added.
- **Duplicated logic:** none. `listEntries` computes `empty` once from the parse it already does; the
  filter only combines three facts; `count` derives from `entries`, so no second count exists.
- **Casts added:** zero.

## 10. Observations

- **The "no state but stray transitions" case cannot be a readable record.** `checkDocument` has
  `rule('transition_ends', ids.has(t.from) && ids.has(t.to))` and `parseDocument` runs it, so an FSM
  with no state and one transition is refused as `corrupt`. The `states.length === 0 &&
  transitions.length === 0` AND is implemented literally, and the test pins the reachable behaviour: the
  record is listed as unreadable and `empty` is false. A record that is "empty by the OR" therefore
  never appears as a normal row.
- **B4 also fails `pnpm check`:** `currentId` is `string | null | undefined`, and the rule's third
  argument is `string | undefined`. The e2e is what pins the behaviour, so the type error was not used
  as the break's evidence.
- **The port 4599 was held by a stale Playwright run** (`cross/titles --project=firefox`) from an
  earlier session, which made the first e2e run fail with `EADDRINUSE`. It was stopped; the run above is
  the one after that.
- Not run: the Firefox and WebKit text-cross projects (not in this task's verification), and the full
  e2e suite (AGENTS.md forbids it locally). A real phone and the live site are the owner's.
