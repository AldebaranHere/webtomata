## Summary of changes

- **Rust engine (`crates/engine-core`):**
  - New `src/language/error.rs`: `LanguageError` has nine variants holding data only
    (`UnexpectedCharacter { position, rest }`, `ExpectedPowerNumber`, `NumberTooLarge`,
    `UnclosedParenthesis`, `UnexpectedSymbol { symbol }`, `UnexpectedEnd`,
    `ExpectedCommaOrBrace`, `UndefinedReference { name }`, `CyclicReference { name }`);
    `key()` is private, `Display` prints the key only, and one `From<LanguageError> for Message`
    maps key and parameters. `InvalidSyntax`, the ten dead syntax messages, the two fixed-list arms
    and `DepthExceeded` are gone.
  - `src/language/parser.rs`: every reachable site returns a typed variant; `NumberTooLarge`
    replaces the library's English text (only `PosOverflow` is possible and the comment says why);
    `try_parse_set_builder` and the predicate subtree return `Option` (a failure means "not a
    set-builder", which is what the caller did with the discarded error); the relation operator is
    the private `RelOp` enum.
  - `src/api.rs`: the three language sites use `.map_err(Message::from)`; `api.invalid_language`,
    `api.enumeration_failed` and the `detail` parameter are gone.
- **Web (`web/src/lib`):** 11 keys in `id.ts`/`en.ts` (the nine errors, the generic sentence, and
  `api.invalid_environment`, which had no text before); `formatGrammarError` moved from
  `grammar/grammar-error-text.ts` to `engine/error-text.ts` as
  `formatEngineError(error, translate, genericKey)`; the three grammar callers pass
  `'grammar.error.generic'`; `LanguageWorkstation.svelte` keeps `error: Message | null` and derives
  the text, so a locale switch re-translates an open banner, and a caught exception shows the
  generic key instead of `err.message`. `eslint.config.js` allowlists the new wasm test.
- **Docs:** `docs/decisions/0070-language-errors-are-keys.md`, `docs/glossary.md`, `PLAN.md`.

## The eight messages that never reached the screen (deleted)

All were built inside `try_parse_set_builder` (`parser.rs:319-400` before the change) and discarded
by `parse_set`'s backtracking (`if let Ok(...)`, then a reset to the finite-set parser): `Bukan
predikat` (334), `Diharapkan ':' atau '|'` (381), `Diharapkan '}'` (392), `Diharapkan 'prefix(w)'
atau 'suffix(w)'` (515), `Diharapkan '#' pada posisi …` (607), `Diharapkan karakter setelah '#'`
(616, 673, 686), `Sintaks predikat hitungan tidak lengkap` (695), `Diharapkan operator relasi
(>=, <=, ==, =, >, <)` (731). The two `_` arms (583, 787) could not be reached even there: they were
the fallbacks of matches over `parse_relational_op`'s fixed eight-token list. `DepthExceeded` was
constructed nowhere.

A malformed set-builder still shows the same sentence as today; two pinning cases say so
(`{ w in {a,b}* : 3#a(w) }` and three others).

## Deepening pass

1. **New exports and public members.**
   - `LanguageError` (nine variants) is public because `engine-core`'s callers and tests match it;
     `key()` is private, and `Display`/`From` both call it, so no key string is written twice.
   - `RelOp` is private to `parser.rs`; nothing outside the parser needs it.
   - `formatEngineError(error, translate, genericKey)` replaces `formatGrammarError`; it is the
     single formatter for both workstations. No wrapper is left at the old path (both old files are
     deleted).
   - The 11 message keys have no duplicate; `genericKey` is the only new argument.
   - No test-only seam was added: the wasm test calls the public engine, the helper test calls the
     public helper, and the Rust tests use `parse`/the evaluator/`api`.
2. **The interface is smaller than the work behind it.** One enum, one conversion, one UI helper,
   and six fewer parser error paths; `try_parse_set_builder` returns a payload-free failure.
3. **Casts added: 0.** The formatter narrows `error.key` with the `MessageKey` type predicate (the
   T-028 `as MessageKey` is gone), the workstation's `as never` is gone, and the wasm test's raw
   call assigns `JSON.parse` to a typed local without an `as`. Two casts were removed.
