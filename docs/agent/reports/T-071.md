## 2. What changed

- **One scheduled query** (`query.ts`, `createQuery`): the newest document, a sequence number, a delay (default 200 ms), an answer for an older document dropped, nothing after `dispose`, and `status`/`value`/`problem`/`subscribe`/`schedule`/`retry`/`dispose`. Six options, as amended: `ask`, `toValue(answer, doc)`, `empty()`, `emptyAtSchedule` (default false), `keepsProblem` (default true) and `delayMs`. `createChecker` (48 lines now) and `createDeterminism` pass their rules; both keep their names, interfaces and the editors' call sites. `CheckStatus` and `DeterminismStatus` are aliases of `QueryStatus`, so the public names stay.
  - `empty()` is needed by both callers even with `emptyAtSchedule: false`, because both clear the value on a refused answer and on a throw.
  - `keepsProblem: false` is the determinism's rule: any thrown error is `failed` and no problem is kept; with `true`, a cancelled call goes back to `idle` with no problem (the checker, as before).
- **One tester** (`tester.ts`): `createTester<D, O extends { input: string }>`. The FSM's 11 calls (`run`, sometimes `delayMs`) are unchanged and get `documentsEqual` by default. Any other document must pass `sameDocument`, enforced by two overloads: a `PdaDocument` is not a `MachineDocument`, so the FSM's equality cannot be omitted or passed (both are `@ts-expect-error` type tests). `pda-tester.ts` is deleted; `pda-tester.test.ts` became `tester.pda.test.ts`.
- **One window** (`list-window.ts`, `windowRows(rows, limit)`): `shownRows` (`pda-run.ts`), `windowEarlierRows` (`grammar-to-pda.ts`) and `listWindow` (`pda-conversion.ts`, with `rulesWindow` over it) are one-line calls. The limit stays where it was (`SHOWN_ROWS`, `CFG_PDA_STEP_WINDOW`, the `50` in `listWindow`), so no new constant is introduced. One identity change, invisible and untested: `windowEarlierRows` now returns a copy below the limit instead of the same array.
- **One grammar text** (R3): the definition stays `grammarToText` in `grammar/grammar-text.ts`; `grammarText` in `pda-conversion.ts` is one line over it, with both names kept so no test is edited. New permanent test: `pda-conversion.grammar-text.wasm.test.ts` compares the two on the wcwᴿ grammar (76 rules, from RNF then CFG in the real engine), on the nine presets, and on an ε body.
- **One refusal mapping**: `unknownSymbolText(message)` in `run-text.ts` (the `input.unknown_symbol` key, the symbol, the place counted from 1); `refusalText` and `pdaRefusalText` call it. `PdaText` and `Text` are structurally the same, so no cast.

## 3. The `grammarText` question (3b / R3)

Tested, not guessed. Before the change, a temporary wasm test compared `grammarText` and `grammarToText` on every input I could produce and all were identical: the 9 grammar presets (`CNF_ORDER` 4 rules, `CNF_NULLABLE` 7, `CNF_START_LONG` 2, `CNF_UNIT_CHAIN` 6, `CNF_SHARED_TAIL` 5, `CFG_PAL` 5, `CFG_PAREN` 2, `CFG_ANBN` 2, `CFG_EQ` 3), the T-037 fixtures through the real engine (`wcwR` 76 rules/22 heads, F-ONE 331/19, F-SPLIT 31/13, and the CNF outputs of `wcwR` 33/17 and F-SPLIT 12/7), and five hand-made edge grammars (no rules, ε start, a multi-character terminal, a start symbol that appears later, an empty start symbol). They are the same algorithm; the only difference is the signature: `grammarToText` takes `emptySymbol = 'ε'`, which `grammarText` did not, and `grammar-text.test.ts:53` tests it with `'λ'`. Hence one definition in `grammar-text.ts` and this name delegating.
