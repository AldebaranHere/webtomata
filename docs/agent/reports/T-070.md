## 2. The by-hand pairs and the engine's answer

The transitions of G are sorted by `comparePdaTransitions` before they reach the engine, so the
rows are:

| index | from | read | pop | push | to |
| --- | --- | --- | --- | --- | --- |
| 0 | q0 | ε | ε | ε | q1 |
| 1 | q0 | a | ε | A | q0 |
| 2 | q0 | b | A | ε | q1 |
| 3 | q1 | b | A | ε | q1 |

By hand, from `determinism` (`crates/engine-core/src/pda.rs:317`): i=0/j=1 share the state, one
reads ε, and pop ε is a prefix of ε → `(0,1)`. i=0/j=2 share the state, one reads ε, and pop ε is a
prefix of A → `(0,2)`. i=1/j=2 read a and b → not competing. i=2/j=3 leave different states → the
loop breaks. Two pairs.

## 10. Deepening pass

- **New exports:** `dashedEdges` and `extraMarkedEdges`. Each has exactly one caller (`PdaEditor`)
  and its own unit tests; neither is exported only for a test, and neither can be private because
  the editor and the tests both need them. `alsoChosenEdge` stays private in the component.
- **New public members:** `dashed` and `alsoChosen` on `EditorCanvasProps`/the drawing's props. Both
  are optional, both are used by `PdaEditor`; the FSM and the read-only views pass neither. The
  `EditorCanvas.type.test.ts` objects still satisfy the interface (optional members).
- **Duplicates:** the `"from>to"` key format now appears in the two functions and in the drawing,
  where `taken` already used the same strings. A shared helper would have to be exported from a
  module that both the drawing and the determinism module import (or live in `geometry.ts`, which
  this task must not touch), so the four one-line template strings stay; the ADR records it.
- **No logic twice:** the class decision in the drawing is one helper; `chosen()` is untouched;
  `extraMarkedEdges` computes the marks' edges once and subtracts the selected key once.
- **Casts added: 0.** (No `any`, no `@ts-ignore`, no `as unknown as`.)
