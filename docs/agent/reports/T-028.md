# Report — Task T-028: Grammar engine errors are keys with parameters

- **Branch:** `task/T-028-grammar-errors-as-keys` (cut from `origin/staging` at `d890cb3`; not pushed)
- **Status:** done

## Summary of changes

- **Rust engine (`crates/engine-core`):**
  - Replaced `GrammarError` (`crates/engine-core/src/grammar/error.rs`) with six typed data variants: `EmptyGrammar`, `RuleWithoutArrow { line: String }`, `EmptyRuleHead`, `NotChomskyNormalForm`, `TooManyNullable { rule: String, limit: usize }`, and `InputTooLong { length: usize, limit: usize }`. Removed unreachable `MissingStartSymbol` and unused `InvalidRuleFormat`, `UnexpectedToken`, `BudgetExceeded`.
  - Added single-source-of-truth `GrammarError::key(&self)`, `impl From<GrammarError> for Message`, and `Display` printing the message key only.
  - Updated `parser.rs` (taking start symbol from `rules.first()` with no `ok_or`/`unwrap`), `cnf.rs`, `cyk.rs`, and all five grammar functions in `api.rs` (`parse_grammar`, `transform_to_cnf`, `cyk_parse`, `cfg_to_pda_topdown`, `cfg_to_pda_bottomup`) to use `Message::from` with no `detail` parameter.
- **Web i18n & UI (`web/src/lib`):**
  - Added six keys in `web/src/lib/i18n/id.ts` and `en.ts` next to `grammar.cyk_input_too_long`: `grammar.error.empty`, `grammar.error.no_arrow`, `grammar.error.empty_head`, `grammar.error.not_cnf`, `grammar.error.too_many_nullable`, and `grammar.error.generic` (marked `TODO(review)`).
  - Created `web/src/lib/grammar/grammar-error-text.ts` (`formatGrammarError`) and wired it into `GrammarWorkstation.svelte`, `GrammarCykTester.svelte`, and `GrammarToPdaTab.svelte`.
  - Deleted `formatCfgPdaRefusal` (and its 3 now-unused imports) from `grammar-to-pda.ts` and its old `detail`-fallback test from `grammar-to-pda.test.ts`.
  - **Side fix:** `GrammarWorkstation.svelte` now stores `pipelineError: Message | null` and derives `errorMessage` via `$derived`, so switching `id` ↔ `en` immediately re-translates an open error banner (matching `GrammarCykTester.svelte` and `GrammarToPdaTab.svelte`).
  - Added `src/lib/grammar/grammar-errors.wasm.test.ts` to the `*.wasm.test.ts` allowlist in `web/eslint.config.js`.
- **Docs:** Added `docs/decisions/0069-engine-errors-are-keys.md`, added `TODO(review)` glossary note in `docs/glossary.md`, updated `docs/agent/PLAN.md`.

## Deepening pass

1. **New exports and public interface members:**
   - Rust `GrammarError` variants (`EmptyGrammar`, `RuleWithoutArrow`, `EmptyRuleHead`, `NotChomskyNormalForm`, `TooManyNullable`, `InputTooLong`): required public enum variants consumed by `engine-core` callers and tests. Helper `GrammarError::key(&self)` is private; `Display` and `From<GrammarError> for Message` both call it so no key string is duplicated.
   - `web/src/lib/grammar/grammar-error-text.ts`: exports only `formatGrammarError` (the single UI helper). `isSharedMessageKey` is private. No duplicate logic remains across `GrammarWorkstation.svelte`, `GrammarCykTester.svelte`, or `GrammarToPdaTab.svelte` (deleted `formatCfgPdaRefusal`).
   - `web/src/lib/i18n/{id,en}.ts`: 6 new keys, zero duplication across dictionaries.
2. **Interface vs. implementation:** One 1-function TS surface (`formatGrammarError`) and one `From<GrammarError> for Message` impl cover all 6 error variants and all 3 UI surfaces.
3. **Casts added:** **1** (`error.key as MessageKey` inside `formatGrammarError` in `web/src/lib/grammar/grammar-error-text.ts:23`), guarded immediately above by `if (hasKey(error.key))` with a safety comment explaining why it is safe (needed so callers/tests can inject a custom `hasKey: (key: string) => boolean` predicate for lazy dictionaries without requiring callers to write type predicates).
